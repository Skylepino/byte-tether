# Daily Interest Digest — Spec

A once-a-day discovery digest: what showed up in the AI/agent tooling ecosystem
that I haven't seen before, plus what I could actually do with each thing.

Runs via an Orca automation. Output lands in `output/YYYY-MM-DD.md`.

---

## Hard rules

1. **Deduplicate against history.** Before writing, read `output/INDEX.md` and every
   dated file in `output/`. Anything already listed in the last **90 days** is banned.
   This is the single most important rule — a digest that repeats yesterday is worthless.
2. **10 items per category, 6 categories = 60 items.** If a category is genuinely
   dry, ship fewer and say so in a one-line note. Never pad with filler.
3. **Every item needs a "What I'd use it for" line** — concrete and specific to
   *my* setup (Laravel/Inertia + React + Postgres, Orca, opencode/codex/agy,
   agent skills in `~/.agents/skills`). Generic restatements of the README are useless.
4. **Verify before you list.** Each item must be fetched or queried, not recalled from
   training. Include a real URL. If you can't reach the source, drop the item.
5. **Date-stamp everything.** Use the real current date from the environment, not an
   assumed one.

## Categories and sources

### 1. Agent skills (10)
Source: `npx --yes skills find "<keyword>"`, and `https://skills.sh`.
Search across distinct keyword families each run — vary them so you don't re-draw
the same well: `agent-skills`, `claude-code`, `mcp`, `test`, `refactor`, `security`,
`laravel`, `react`, `observability`, `prompt`, `skill-creator`, etc.
Install hint if it looks useful: `npx --yes skills add owner/repo@skill --global --agent universal -y`.

### 2. GitHub projects (10)
Source: GitHub Search API.
`https://api.github.com/search/repositories?q=created:>{date-30d}+topic:ai-agent&sort=stars`
Vary the topic/query per run (`ai-agent`, `llm`, `mcp-server`, `agent-framework`,
`developer-tools`, `claude-code`, `rag`, `eval`, `coding-agent`, `local-llm`).
Prefer repos created in the last ~60 days that show early traction.
Note the language, rough star count, and whether it has releases.

### 3. CLI tools (10)
Source: GitHub search + `https://cli.im` / awesome-lists for terminal tools that
improve an agent's loop: better ripgrep, file watchers, AST/codegen CLIs, git tooling,
terminal AI clients, shell completions, tUI frameworks.
Note install method (brew/scoop/npm/cargo/go/pip/uv) and whether it's Windows-safe.

### 4. MCP servers (10)
Source: `https://github.com/modelcontextprotocol/registry`, awesome-mcp-servers lists.
Prefer servers that add real capability to Orca/opencode/codex — filesystem, git,
databases, browser automation, issue trackers, observability.
Note the transport (stdio/http) and one example tool call.

### 5. Agent frameworks & orchestration (10)
Source: GitHub search + blog feeds.
Anything in the Orca / graphify / ponytail / vibe-wise orbit: harnesses, multi-agent
orchestration, task DAGs, handoff protocols, evals harnesses, agent memory,
context engineering, MCP gateways, agent sandboxes.
This is the category I most care about — read these closer and write richer notes.

### 6. Papers & writing worth reading (10)
Source: `https://dev.to/feed/tag/ai`, `https://dev.to/feed`,
`https://daily.dev/rss.xml`, arXiv listings.
Skip SEO filler and "10 best X" listicles. Want: real technique, real benchmarks,
post-mortems, architecture write-ups, eval methodology.
Note reading time and one sentence on why it's worth my time.

## Output format

Write **two** files per run.

### `output/YYYY-MM-DD.md`

```markdown
# Daily Interest Digest — YYYY-MM-DD

_<one-line mood summary of the day>_

## Agent skills (10)
1. **owner/repo@skill** — what it is, one line.
   → *Use for:* concrete application in my setup.
   <url>

## GitHub projects (10)
...

## CLI tools (10)
...

## MCP servers (10)
...

## Agent frameworks & orchestration (10)
...

## Papers & writing (10)
...

## Thread of the day
_If 2–3 items across categories connect into one idea, name it here. This is the
section I actually read._

---
_Generated by Orca automation · sources: skills.sh, GitHub Search, MCP registry,
dev.to, daily.dev_
```

### `output/INDEX.md`

Append one row per item, newest first. This is the dedup ledger:

```markdown
| Date | Category | Item | URL |
|------|----------|------|-----|
| 2026-10-09 | skills | owner/repo@skill | https://... |
```

Read this **first** on every run. It is what makes the digest non-repetitive.

## Media (optional, only if a key is configured)

If `DEVTO_API_KEY` is set in the environment, also render a social card and POST to
dev.to. **Skip silently if the key is absent — never fail the digest over it.**

- Generate a 1000×420 PNG cover (the `imagegen` skill, or an image API if configured)
- `POST https://dev.to/api/articles` with `api-key` header, body: title, body_markdown,
  published: true, tags, cover_image, canonical_url
- **Draft, not publish.** Set `published: false` and hand back the edit URL so I
  proofread before it goes live. Auto-publishing unreviewed AI output under my name
  is not something to do by default.

Never commit secrets. Read keys from the environment only.

Sites with real signal, no engagement bait:

- **Lobsters** (`lobste.rs/rss`) — smaller, higher-signal dev crowd

- **Papers with Code** — benchmark results, not just claims
- **Anthropic / OpenAI engineering blogs** — RSS, first-party technique
- **Simon Willison's blog** (`simonwillison.net/atom/everything/`) — pragmatic LLM tooling
- **Dan's newsletter / The Batch** — weekly, curated
- **Awesome lists** (`sindresorhus/awesome`, `awesome-mcp-servers`) — discovery, not reading
- **Changelog / This Week in ML** — release radar

## How this runs

**Orca automation**, daily at 18:00 Asia/Manila, provider `codex`, repo `Byte-Tether`.

```bash
orca automations list --json
orca automations runs --id <id> --json
orca automations run <id> --json      # trigger manually
orca automations edit <id> --time 08:00 --json
```

**Catch-up on launch.** The 18:00 schedule is the floor, not the whole story.
If Orca was closed at 18:00 and the last digest is >20h old, run it immediately.
Implementation is a startup script that checks `output/INDEX.md`'s newest date
against now and fires `orca automations run` if stale.
