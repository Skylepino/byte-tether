## Papers & writing (10)

Reading times are estimates from the fetched abstract/entry length — these sources do not state
them. `daily.dev` was fetched and **discarded**: every current entry was a "Where to read about
X" listicle, exactly the filler the config tells us to skip.

1. **One Skill Too Many: How Co-Installed Skills Conflict in Coding Agents** — arXiv:2610.11647v1
   (~4 min, abstract). Skills arrive from independent sources — teams, plugins, copied collections
   — and when two do the same job the model picks between them by *name and description alone*,
   with the loser silently losing.
   → *Worth it because:* this is a direct measurement of the thing today's skills list makes worse.
   You have a `~/.agents/skills` directory and ten new entries in this digest alone, several of
   which overlap (`tdd` and `test-driven-development`; `safe-refactor` and `request-refactor-plan`).
   Read it before installing all ten.
   https://arxiv.org/abs/2610.11647

2. **Cadence: Strategic Guidance for Coding Agents** — arXiv:2610.12269v1 (~4 min). Runtime
   monitors that read execution trajectories and inject corrective guidance. Existing monitors use
   fixed inspection intervals, which miss severe misbehaviour while burning checks on nothing.
   → *Worth it because:* it replaces "check every N steps" with a policy for *when* to intervene —
   the cheapest possible lever on an agent's mid-task derailment.
   https://arxiv.org/abs/2610.12269

3. **Where Do the Tokens Go? Understanding and Reducing Costs in LLM Agents** — arXiv:2610.11602v1
   (~5 min). Multi-axis open-coding study of 200 CyberGym traces across four agents — Codex,
   **OpenCode**, Cybench and EnIGMA — under an unaided baseline.
   → *Worth it because:* it bills the failure explicitly. An agent can spend a fortune and still
   produce no working PoC, and this is the first study on the list that includes the exact client
   you run daily.
   https://arxiv.org/abs/2610.11602

4. **One Word Opens the Gate: The Option-Channel Attack on Typed Decision Models as Agent
   Guardrails** — arXiv:2610.12292v1 (~4 min). Typed decision models read text and return a
   probability over caller-defined options with no generated text; increasingly they sit in agent
   systems as the guardrail that approves or blocks a tool call. This attacks that.
   → *Worth it because:* a guardrail that can be talked past with one word is worse than no
   guardrail, because it looks like a control. Read before adopting any approval-gate pattern —
   including from the jev-judge tools visible in today's MCP registry.
   https://arxiv.org/abs/2610.12292

5. **OnTrack: Real-Time Monitoring and Intervention in LLM Agent Trajectories** —
